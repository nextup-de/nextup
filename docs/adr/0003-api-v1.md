# 0003 API v1

## Status

Accepted · PILOT/ARC · 2026-11

## Context

Customers' middleware needs a stable way to read cases, decisions, projects and the org chart, and to raise a case
from another system. Today there is only the pull API of `apps/app/src/app/api/[company]/events/route.ts` and
`apps/app/src/app/api/[company]/knowledge/documents/route.ts`, authenticated by a company-scoped bearer token
(`ApiToken.scopes` in `apps/app/prisma/schema/auth.prisma`). The shapes must be fixed before the API phase builds
them (D3: public contracts are only extended).

## Decision

All schemas are exported from `@nextup/contracts/public` (`packages/contracts/src/public/api-v1.ts`); the table is
the const `ApiV1`. Nothing in `apps/app/src` imports it yet (D10).

- **Base path**: `API_V1_BASE` = `/api/v1/[company]`. The tenant is the `[company]` segment.
- **Auth**: a company-scoped bearer token with scopes (`ApiToken`). Each endpoint names one scope.
- **Paging**: by cursor. A list takes `ApiV1ListQuery` (`cursor` optional, `limit` 1-200, default 50) and answers
  with `data` and `page: ApiV1PageInfo` (`nextCursor`, null on the last page).
- **Errors**: `ApiV1Error` = `{ error: { code, message (max 500), requestId } }`, `code` one of `bad_request`,
  `unauthorized`, `forbidden`, `not_found`, `conflict`, `rate_limited`, `internal`.
- **Idempotency**: `ApiV1CaseCreate.externalId` is the caller's key; a second create with the same value returns
  the first case.

| Id | Method | Path | Scope | Query | Request | Response |
|---|---|---|---|---|---|---|
| `cases.list` | GET | `/cases` | `cases:read` | `ApiV1ListQuery` | - | `ApiV1CaseList` |
| `cases.get` | GET | `/cases/{id}` | `cases:read` | - | - | `ApiV1Case` |
| `cases.create` | POST | `/cases` | `cases:write` | - | `ApiV1CaseCreate` | `ApiV1CaseCreated` |
| `decisions.list` | GET | `/decisions` | `decisions:read` | `ApiV1ListQuery` | - | `ApiV1DecisionList` |
| `projects.list` | GET | `/projects` | `projects:read` | `ApiV1ListQuery` | - | `ApiV1ProjectList` |
| `projects.get` | GET | `/projects/{id}` | `projects:read` | - | - | `ApiV1Project` |
| `org.get` | GET | `/org` | `org:read` | - | - | `ApiV1Org` |

Bodies are built from the canonical model (ADR 0001): `CaseRef`, `Decision`, `ProjectRef`, `OrgUnit`, `Role`,
`RoleHolder`. No endpoint returns a per-person count, score or rank (D6).

- The existing `/api/[company]/events` stays as it is (D3); API v1 runs next to it.
- **Visibility**: user tokens will see only what the user may see (VIS); system tokens get no per-person data (D6).
- **OpenAPI**: the API phase generates the OpenAPI document from `ApiV1`, so the table is the single source.

## Consequences

- The API phase implements routes against these schemas and needs no further shape decisions.
- A breaking change to any schema is a new version (`/api/v2`) next to v1; additions are optional fields or new
  endpoints.
- Scopes are strings of the form `<area>:(read|write)`; token configuration stays data (D4).
